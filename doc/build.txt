

                              Building NTL
                              ============


This document covers building NTL from source.  NTL uses Meson + Ninja
as its build system; the legacy Perl `./configure` + Makefile build
was removed in NTL 12.0.  If you have a script that calls
`./configure && make`, see `doc/migration-from-makefile.txt`.


Section 1.  Quick start (native build)
--------------------------------------

From the top of the source tree:

    meson setup build
    meson compile -C build
    meson test -C build
    meson install -C build --destdir /tmp/ntl-install

The resulting libntl, headers, and ntl.pc are installed under the prefix
(default /usr/local) below /tmp/ntl-install.


Section 2.  Cross-compiling
---------------------------

The build supports cross-compilation without executing any
target-architecture binary during configuration.  The list of supported
target triplets is in src/meson/abi-tables/.  To cross-compile, supply a
Meson cross-file:

    meson setup --cross-file=ci/cross-files/aarch64-linux-gnu.txt build-arm
    meson compile -C build-arm

See specs/001-meson-cross-compile/quickstart.md for worked scenarios for
several common targets.


Section 3.  Supported targets
-----------------------------

(See src/meson/abi-tables/ for the authoritative list.)

   x86_64-linux-gnu             aarch64-linux-gnu        x86_64-apple-darwin
   x86_64-linux-musl            aarch64-linux-musl       aarch64-apple-darwin
   i686-linux-gnu               armv7l-linux-gnueabihf-musl
                                powerpc64le-linux-gnu    x86_64-w64-mingw32
                                                         i686-w64-mingw32
                                x86_64-unknown-freebsd   riscv64-linux-gnu


Section 4.  Configuration options
---------------------------------

See `meson configure build` for the full list, or read meson.options at
the root of the source tree.  Common options:

   -Dthreads=true|false                Enable thread support
   -Dexceptions=true|false             Enable C++ exceptions
   -Dgmp=enabled|disabled|auto         Use GMP for long-integer arithmetic
   -Dgf2x=enabled|disabled             Use GF2X for GF(2)[X] multiplication
   -Dtune=default|generic|x86|         Tune-parameter source. "default" picks
        linux-s390x|host                  per target; "host" reads
                                          src/meson/tune-tables/host-tuned.ini
                                          (produced by ntl-wizard).
   -Ddisable_longdouble=true|false     Suppress long-double code paths


Section 5.  Auto-tuning with the Wizard
---------------------------------------

For host-CPU-tuned `libntl` performance, NTL ships a Python tool
`ntl-wizard` which replaces the legacy Perl Wizard.  See
`doc/wizard.txt` for usage.  Quick start:

    pip install ./tools
    ntl-wizard --batch
    meson setup -Dtune=host build
    meson compile -C build

The Wizard runs only on native build hosts; cross-compile builds use
the static tune tables and ignore any host-tuned artifact.


Section 6.  Limitations
-----------------------

   *  On Windows, only MinGW-w64 is supported.  MSVC support is out of
      scope.  The Windows build is currently flagged "experimental":
      symbol export is coarse-grained (everything is exported); binary
      compatibility across NTL releases is weaker than on ELF platforms.

   *  Long-double-dependent code paths are automatically suppressed on
      all Apple and all MinGW targets because long double on these
      platforms is 64-bit IEEE rather than the wider forms NTL prefers.
